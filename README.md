>
> 入群 / 退群事件依赖运行时注入订阅（intent `1<<24`，`GROUP_MEMBER_ADD` / `GROUP_MEMBER_REMOVE`），
> 插件启用该订阅时会触发一次 **WebSocket 受控重连**。表现为：**首次开启的瞬间（以及重载导致订阅重新注入时），
> 机器人可能断开几秒到十几秒**，期间收发消息中断，重连完成后自动恢复，**不需要重启 AstrBot**。
> 建议在群内不活跃的时段开启；如果你跑着主动消息推送等敏感业务，请避开这个时间窗口。

自带 WebUI 管理面板。**不修改 AstrBot 本体代码、零第三方依赖。**

## 功能一览

| 模块 | 能做什么 |
| --- | --- |
| 禁言 | `/群管 禁言` 多时长写法 + 理由；`禁言 解除`、`禁言 名单`、`禁言 历史`（按成员 / OpenID 前缀查）；旧写法 `/群管 解禁`、`/群管 查禁言`、`/群管 禁言历史` 仍可用（**1.6.0 移除**） |

| 欢迎语 | 审批通过的欢迎语、机器人入群自我介绍 |
| 成员档案 | `member_openid ↔ 昵称/备注` 对照表，解决官方不给昵称的问题；退群通知从中取名 |
| 退群回收 | 机器人被移出群（`GROUP_DEL_ROBOT`）后自动删掉该群的成员档案、群规、判定记录、禁言/撤回历史等；`bot_state` 二次确认，查不了（`11253`）不误删；`/群管 状态 群` 可手动巡检 |
| 群规审核 | 引用违规消息发 `/群管 举报`，四维度判定 → 自动撤回 + 禁言 + 说明依据 |
| 判定留痕 | 每条判定都存原文（前 1000 字）+ 耗时/token + 结论；记录页点「原文」看详情、可导出 CSV、可标「误判 / 正确」（标注会持久化进提示词示例） |
| 成本防护 | 同群模型调用排队上限（默认 3）、单次超时（默认 45s）、每日调用熔断（默认 500 次）；`/群管 状态 自检` 一条命令看清链路与用量 |

| 词典 | 2 个最小内置词库（406 条）、上传自定义词库、白名单、命中测试 |
| 管理面板 | 九个页签，配置可搜可分组编辑，多数即时生效 |

## 快速开始

**第一步：群侧四项设置（决定功能上限，每个群都要设）**

| 设置 | 要求 | 说明 |
| --- | --- | --- |
| 群聊消息范围 | 群主设为「获取群内全部消息」 | 否则机器人只收到 @ 它的消息 |
| 事件订阅 | 开放平台 → 回调配置勾选 `GROUP_MESSAGE_CREATE` | Webhook 模式必做 |
| 机器人身份 | 设为群管理员 | 决定能否撤回他人消息，未设会报 `11703` |
| 撤回时限 | 官方硬限制 2 分钟（`40064004`） | 管理员只扩大「能撤谁」，不延长时限 |

**第二步：装插件、发指令**

1. 插件目录放进 AstrBot 的 `plugins/`（别多套一层），重启或重载；
2. 群里发 `/群管` 看指令树，发 `/群管 帮助` 看用法。

> 只发 `/群管` 会先提示「参数不足」再列指令——这是 AstrBot 指令组的默认行为，不是报错。

## 指令速查

指令统一在指令组 `/群管` 下，写法 `/群管 <子指令>`；不带 `/` 时必须 @ 机器人。
**指令名与被 @ 成员之间要有空格**：`/群管 禁言 @某人 10分钟` ✅，`/群管 禁言<@某人>10分钟` ❌。

| 指令 | 用途 |
| --- | --- |
| `/群管 禁言 @用户 时长 [理由]` | 时长支持 `10分钟` / `2小时` / `1天`，与理由顺序可互换；同时 @ 多人只处理第一个 |
| `/群管 禁言 解除 @用户`<br/>`/群管 禁言 名单`<br/>`/群管 禁言 历史 [条数\|汇总] [@用户\|OpenID前缀]` | 解禁（可一次 @ 多人）、当前禁言名单、禁言历史流水（默认最近 10 条） |
| `/群管 审批 [页码\|全部]`<br/>`/群管 审批 通过 序号\|昵称`<br/>`/群管 审批 拒绝 序号\|昵称 [理由]` | 入群申请（`全部` 跨群汇总，可加页码）；通过 / 拒绝带按钮通知时也可直接点 |
| `/群管 状态 [日报\|群 [清理]\|自检\|群名]` | 不带参数＝群管日报（待处理申请 + 禁言人数）；`群`＝机器人还在不在已记录的群里；`自检`＝审核链路与用量；`群名`＝刷新本群群名 |
| `/群管 撤回` | 引用消息后发送；或 `/群管 撤回 <message_id>` |
| `/群管 群规 [列表\|添加\|设置\|删除\|清空]` | 添加示例：`/群管 群规 添加 刷屏 \| 连续刷无意义内容 \| 10分钟`（半角 / 全角竖线、纯空格均可） |
| `/群管 审核 [试跑\|巡检\|测试\|自我介绍]` | 诊断入口，看状态、切换试运行、试判一条内容 |
| `/群管 成员` | 成员档案查询与维护 |
| `/群管 管理登记 [列表\|取消]` | 主动登记为审核提醒名单，变体累计提醒只 @ 名单内的人 |
| `/群管 举报` | 引用违规消息触发审核（全体成员可用） |
| `/群管 帮助` | 完整指令速查（面板里也有一份可视版） |

### 指令迁移说明（重要）

1.5.0 起，功能相近的指令合并成 5 个大类（禁言 / 审批 / 状态 / 审核 / 群规），**同一功能有新旧两种写法**：

- **现在**：新旧写法**都能用**，行为、参数、权限完全一致；**但请优先用新写法**，本文档所有示例都已改成新写法。
- **1.6.0 起**：**旧写法全部移除**（不只是文档不写，插件里也不再兼容），届时还敲旧指令会直接失效。

| 旧写法（1.6.0 移除） | 新写法（推荐，1.5.0 起） |
| --- | --- |
| `/群管 解禁 @用户` | `/群管 禁言 解除 @用户` |
| `/群管 查禁言` | `/群管 禁言 名单` |
| `/群管 禁言历史 [汇总] [@用户]` | `/群管 禁言 历史 [汇总] [@用户]` |
| `/群管 通过 N` | `/群管 审批 通过 N` |
| `/群管 拒绝 N [理由]` | `/群管 审批 拒绝 N [理由]` |
| `/群管 汇报` | `/群管 状态` |
| `/群管 体检 [清理]` | `/群管 状态 群 [清理]` |
| `/群管 自检` | `/群管 状态 自检` |
| `/群管 群名` | `/群管 状态 群名` |

需要提醒的是：`/群管 审批`、`/群管 审核`、`/群管 群规`、`/群管 撤回`、`/群管 举报`、`/群管 成员`、
`/群管 管理登记`、`/群管 帮助` 这 8 个指令**一直没变**，只是子命令更规整了。

权限：`/群管`、`/群管 帮助`、`/群管 举报`、`/群管 群规`（只读）全员可用，其余需管理员。
管理员判定由「判定模式 + 启用条件」组成：`any`（默认，满足任一）或 `all`（全部满足）；
条件可选 AstrBot 管理员 / QQ 群角色 / 自定义 OpenID。生效群范围由 `basic.target_group_openids` 控制，
留空＝所有群，也支持 `机器人实例ID:群OpenID` 只让指定机器人管。

## 群规审核怎么工作

> 核心约定：**只有收到 `/群管 举报` 才进入审核**，平时不扫描、不判定。

判定分四层，前两层零成本：

| 维度 | 依据 | 成本 |
| --- | --- | --- |
| 关键词 | 自定义关键词 / 本地词库 / 内置套路正则 | 零成本 |
| 群规 | 命中本群某条规则 | 无额外成本 |
| 语义分析 | 结合上下文（人身攻击、阴阳怪气等） | 调模型 |
| 图片识别 | 被举报消息含图片 | 调多模态模型 |

**时长由代码算，模型无权指定**：命中群规取规则时长；未命中时按严重度（低 10 分钟 / 中 1 小时 / 高 1 天）；
不足 60 秒用兜底时长（默认 600 秒）；上限默认 1 天。

**默认是试运行**：只判定并回话术、不撤回不执行，确认误判率可接受后再关掉试运行。
置信度阈值默认 `0.75`，低于阈值只记录不执行；记录在面板「记录 → 判定记录 / 试跑」，误判可一键标记。

**变体检测**（`袋刷单`、`加·微·信` 这类绕写）只产疑似、**永不自动禁言**，累计后提醒登记过的管理员；
待办队列与复犯累进在同一处配置。开关、阈值、豁免名单、关键词都**按群独立**，改完立即影响下一次判定。

**为什么显示 OpenID 而不是昵称**：官方成员信息接口 `GET /v2/groups/{gid}/members/{openid}` 需要额外权限，
多数应用返回 `11253`，插件静默降级显示 OpenID，不影响禁言 / 撤回 / 审批。用「成员档案」手动补名字即可。

> 想弄清四种维度怎么加权、阈值与试运行怎么配合、豁免名单和复犯累进的实际效果，见
> **[详细手册 docs/GUIDE.md](docs/GUIDE.md)** 的「群规审核」章节。

## 常见问题

**1. 插件加载失败 / WebUI 看不到插件**
目录层级不对或 `metadata.yaml` 不完整。确认路径是 `plugins/astrbot_plugin_qq_group_manager/`，
`name` 与目录一致，`astrbot_version` 满足当前版本；再看 AstrBot 日志的报错。

**2. 指令没反应 / 提示无权限**
逐项确认：管理员判定条件、`basic.target_group_openids` 生效范围、指令格式（不带 `/` 时是否 @ 了机器人）、
对应功能开关是否打开。

**3. 禁言 / 撤回报错**
`11703` 机器人不是管理员；`40064004` 超过 2 分钟撤回时限；`40062003` 非管理员撤他人消息；
`11253` 接口无权限（成员信息、群列表等内邀能力），属正常降级。

**3.1 入群申请没有通知 / 点按钮没反应**
申请通知的主通道是 `GROUP_JOIN_REQUEST` 事件，**机器人必须是群管理员**，否则平台不推、轮询也报 `11703`。
事件没来就等兜底轮询（默认 300 秒），也可发 `/群管 审批` 手动拉一次。
按钮点不动多半是「按钮可点范围」设成了 `admin`（仅群主/管理员）；点了没反馈则是当前 AstrBot
不支持按钮事件（启动日志有告警），先用 `/群管 审批 通过 <序号>`。

**4. 退群 / 入群通知不生效**
先确认「群成员事件」已开启（配置项 `member_event.enable_member_remove_notify`），
开启后按顶部说明会有一次重连；仍收不到通常是平台侧未给该机器人推送该事件。
退群事件不带 `event_id`，无法被动回复，因此默认发主动消息，需要主动消息额度。

**5. 设置改了没生效**
面板里标「即时生效」的项保存即生效；涉及事件订阅的改动需要重载插件（会触发一次重连）。

**6. 明明违规却没处理**
看判定记录里的置信度是否低于阈值、是否还开着试运行、该成员是否在豁免名单、消息是否已超撤回时限。

**7. 成员列表只显示 OpenID**
见上文 `11253` 说明，用「成员档案」补昵称，不影响功能。

**8. 卸载后数据还在？**
插件只删自己的目录，`data/plugin_data/astrbot_plugin_qq_group_manager/` 与配置文件会保留，需手动删除。

更多排障细节见 [CHANGELOG.md](CHANGELOG.md) 对应版本说明。

## 数据与日志位置

| 内容 | 路径（相对 AstrBot 数据目录） |
| --- | --- |
| 插件配置 | `config/astrbot_plugin_qq_group_manager_config.json` |
| 群列表 / 成员档案 / 禁言历史 / 撤回历史 | `plugin_data/astrbot_plugin_qq_group_manager/` 下 `known_groups.json`、`members.json`、`mute_history.json`、`recall_history.json` |
| 群规、审核设置、判定记录 | `plugin_data/astrbot_plugin_qq_group_manager/mod_*.json` |
| 词库与启用状态 | `plugin_data/astrbot_plugin_qq_group_manager/lexicons/`、`lexicon_state.json` |
| 文件日志 | `plugin_data/astrbot_plugin_qq_group_manager/astrbot_plugin_qq_group_manager_YYYYMMDD.log`（默认留 14 天） |

机器人被移出某个群（或 `/群管 状态 群 清理` 检出离群）时，插件会把这个群在上述文件里的记录删掉——
只删该群，其他群不动；想留档就在那之前备份。`basic.enable_group_del_purge` 关掉可只记日志不删数据。

卸载前请备份上述目录与配置文件。
